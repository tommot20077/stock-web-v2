# 模型調度守則(Model Dispatch)

> 目的:讓任何等級的主線模型,把工作切給便宜模型執行而不失控。
> 本專案 GSD 實際參數(查證於 `.planning/config.json`):`model_profile: "balanced"`、`node_repair_budget: 2`、`mode: "yolo"`、`granularity: "standard"`。

## 0. 參數現況與理由

- `model_profile: balanced` **維持不動**。理由:本 repo 測試閘門強(三層測試 + CI;pre-commit 測試 hook 存在但**未確認生效**,見 harness-diagnosis.md 次要-1,別把它算進防線),便宜模型的執行錯誤大多會被測試接住;判斷型工作(安全、契約、架構)本來就該升級到主線或問 Yuan,不靠調 profile 解決。
- `node_repair_budget: 2` 維持——與「同一件事最多兩輪」原則一致(見 §4)。
- 額度注意:部分請求可能被自動導向不同型號;「被導向的請求是否消耗當前高階額度」**未確認**,勿憑記憶假設,建議在 usage 儀表板實測。

## 1. 指揮官不下場

主線(指揮官)只做:判斷、拆解、交辦、驗收、整合。

**主線必須親讀**(不外包):CLAUDE.md、`.planning/config.json`、`ai-docs/` 判斷關鍵檔(security、browser-auth-contract、judgment)、任何要修改的契約文件。判斷力建立在輸入品質上。

**一律派 subagent**:批次 grep/廣度掃描、跑測試、多檔機械修改、網頁查證、read-back 驗證。

## 2. 交辦三要素(缺一不發)

每個 subagent 任務必含:
1. **目標與動機**:做什麼、為什麼(讓它能在模糊處做對的取捨)。
2. **驗收條件**:可檢查的完成定義(哪個測試綠、哪個檔案存在、哪個問題有答案)。
3. **回報格式**:只回結論 + `file:line` 證據;長產物存檔、回傳路徑,不貼全文。

範本見 `ai-docs/task-briefs.md`。

## 3. 回報合約

- Subagent 回報 = 結論、證據(`file:line`)、殘留風險/未確認事項。禁止把整個檔案內容倒回主線。
- 找不到 = 明說「找不到,查過 X/Y/Z」,不編造。
- 主線收到回報後,關鍵結論要抽查(親讀 1-2 個引用的 file:line)再採信。

## 4. 升降級路徑

- 便宜模型錯一次 → 同任務升一級重派,附上失敗產出與原因。
- 中階模型同一子任務連錯兩次 → 帶**完整失敗軌跡**(兩次的輸出與差距)升到主線親自處理。
- 主線解出可重複的模式 → 把模式寫成明確步驟,降回便宜模型批次套用。
- 輪數怎麼算:**同一模型 + 同一策略 = 一條線,每條線最多兩輪**(對齊 `node_repair_budget: 2`);升級模型或換策略開新線並重置計數,但**升級最多兩次**——之後問 Yuan,不無限重試。

## 5. 驗證不自驗

- 檔案類產出:派 fresh-context subagent read-back(它沒有寫入者的偏見)。
- 程式碼類產出:跑測試(backend `./mvnw test`;frontend `npm test`),以輸出為準。
- 高風險判斷(安全語義、契約裁決、刪除類操作):第二意見——再派一個獨立 subagent 從反方立場審,或多方案評審擇優。
- 產出宣稱「已完成」而沒有上述任一證據 → 視為未完成。

## 6. 型號與參數:先查證,不憑記憶

- 派工時顯式指定 model 與 effort;不確定當前可用型號就先查,查不到就標註「未確認」。
- GSD 相關參數一律讀 `.planning/config.json` 實際值,不引用本檔或記憶中的舊值(本檔 §0 的值是 2026-07-07 快照)。
