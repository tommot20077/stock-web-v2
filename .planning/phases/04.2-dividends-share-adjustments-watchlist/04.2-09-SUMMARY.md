## Repository SQL（listSince）

```sql
select asset_id,
       case when reversal_of_id is null then quantity_delta else -quantity_delta end as signed_delta,
       effective_at
from share_adjustments
where user_id = :userId and effective_at >= :since
order by effective_at, id
```

本機以暫時的 PostgreSQL 16 叢集驗證（V17 DDL 原檔 + uuid-ossp / users / assets / prevent_append_only_mutation stub）：使用者 1 的資料有昨日拆股、今日 42 號 +300 再沖銷、今日 41 號同日兩筆 +100 / +200，另有使用者 2 的 +999。`since = 2026-09-03T16:00Z` 時只回使用者 1 的 4 列（42：+300、−300；41：+100、+200），昨日那筆被排除；依資產加總為 41 → 300、42 → 0；使用者 2 的列不出現（T-04.2-21）。`EXPLAIN`（關閉 seqscan）走 `idx_share_adjustments_user_effective`、`Index Cond: user_id = 1 AND effective_at >= …`。驗完已刪除叢集目錄、不留任何 postgres process，`/tmp/claude-0` 一路往下的權限已改回 700。
