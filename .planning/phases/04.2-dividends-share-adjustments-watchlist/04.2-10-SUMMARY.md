## 參數與錯誤（實作現況）

| 參數 | 行為 |
|---|---|
| `type` | `BUY` / `SELL` / `DIVIDEND` / `SHARE_ADJUSTMENT`，trim 後不分大小寫；kind 名稱（`CASH_DIVIDEND`、`SPLIT` 等）也算白名單外 → 400 `VALIDATION_FAILED` `fields.type` |
| `symbol` | trim、轉大寫後經 `AssetFacade.findBySymbol` 查；查無 → 404 `ASSET_NOT_FOUND` `fields.symbol`（同 `/trades`） |
| `dateFrom` / `dateTo` | 用同一個 `ApiTimeParser.parseRangeBound`；作用於 `occurred_at`，半開區間；格式錯或區間顛倒 → 400 `VALIDATION_FAILED`（同 `/trades`，沒有 fields） |
| `sort` | `executedAt` / `createdAt` / `total` / `quantity` → `a.occurred_at` / `a.created_at` / `a.amount` / `a.quantity`；白名單外 → 400 `fields.sort` |
| `direction` | `asc` / `desc`；白名單外 → 400 `fields.direction` |
| `page` / `size` | 非數字 → 400 `fields.page` / `fields.size`；越界夾限 0..10000 / 1..100 |

## Deviations from Plan

### 依契約或現況調整

1. **page=-1 改為夾限，不回 400。** 計畫 Task 2 的 WebMvc 條目寫「`page=-1` → 400 fields」，T-04.2-24 也寫「超過 → 400」。但凍結契約 `GET /portfolio/activities` 一節寫的是「夾限同 GET /trades」，`/trades` 的實作也是夾限（`Math.min(Math.max(0, page), 10000)`、size 1..100），所以依契約。非數字的 `page` / `size` 仍然回 400 並附 fields。DoS 緩解（T-04.2-24）仍成立，因為 size 上限 100。
2. **symbol 查無回 404，不回空頁。** 計畫寫「查無 → 回空頁，與 /trades 行為一致——以 TradingController 現況為準」。現況是 `TradingService#resolveAsset` 回 404 `ASSET_NOT_FOUND` `fields.symbol`，依現況實作。
3. **錯誤附 fields 的範圍比 `/trades` 大。** `/trades` 的 sort / direction / page / size 錯誤沒有 `error.fields`；本端點依契約與計畫附上 `fields.type` / `fields.sort`，另外為一致性加上 `fields.direction`、`fields.page`、`fields.size`。這是加法，`/trades` 沒動。
4. **Commit scope 用 `04.2-10`。** 計畫 `<repo_and_branch>` 寫 `feat(trading)` / `test(start)`，改依 orchestrator 指示與 AGENTS 慣例。

### 結構

5. **[Rule 3 - Blocking] 兩個 enum 骨架提前到 Task 1。** `ActivityTypeFilter` / `ActivitySortKey` 原屬 Task 2，但 `ActivityRepository.ActivityQuery` 與預設排序需要它們，所以 Task 1 先建立常數與 SQL 片段；`fromApiValue` 解析留在 Task 2 以 RED → GREEN 完成。
6. **[Rule 2 - 缺測試] 新增 `JdbcActivityRepositorySqlTest`（計畫檔案清單外）。** 計畫的 behavior「DIVIDEND 只啟用 cash_dividends 分支、BUY / SELL 加 `t.type = :tradeType`」本機沒有 Docker 就無法以 IT 驗收，所以把 SQL 組成抽成 package-private 的 `listStatement` / `countStatement`，不連資料庫斷言分支選擇、參數繫結與 ORDER BY 字面。
7. **symbol / 日期條件放在外層別名 `a`，不放進每個分支。** 擁有者條件仍在每個分支內（T-04.2-22）。本機 `EXPLAIN` 證實 PostgreSQL 會把外層條件推進三個分支的索引條件，效能不受影響。
8. **WebMvc 切片放真的 `ActivityQueryService`**（只 mock repository 與 AssetFacade）。計畫的介面讓 service 收原始字串，如果 mock 掉 service，切片內就驗不到「type=FOO → fields.type」；用真 service，參數解析才真的被執行。
