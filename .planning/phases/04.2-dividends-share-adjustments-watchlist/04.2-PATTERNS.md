### `BE: V16__dividends_and_share_adjustments.sql` (migration, append-only)

**Analog:** `BE: stock-db-migration/src/main/resources/db/migration/V15__cash_ledger_entries.sql`

Copy wholesale: table shape, constraint naming, index, and **reuse** `prevent_append_only_mutation()` (already defined in V15; do NOT redefine — just `CREATE TRIGGER`). Write a new `validate_<table>_reversal()` per table following V15's function.

Table + constraints (V15 L17-55):
```sql
CREATE TABLE cash_ledger_entries (
    id              BIGSERIAL PRIMARY KEY,
    uuid            UUID           NOT NULL DEFAULT uuid_generate_v4(),
    user_id         BIGINT         NOT NULL REFERENCES users(id),
    ...
    idempotency_key VARCHAR(128)   NOT NULL,
    reversal_of_id BIGINT REFERENCES cash_ledger_entries(id),
    CONSTRAINT uk_cash_ledger_entries_uuid UNIQUE (uuid),
    CONSTRAINT uk_cash_ledger_entries_user_idempotency UNIQUE (user_id, idempotency_key),
    CONSTRAINT uk_cash_ledger_entries_reversal_of UNIQUE (reversal_of_id),
    CONSTRAINT ck_cash_ledger_entries_amount_positive CHECK (amount > 0)
);
CREATE INDEX idx_cash_ledger_entries_user_occurred
    ON cash_ledger_entries (user_id, occurred_at DESC, id DESC);
```
Triggers (V15 ~L72-83) — repeat for each new table:
```sql
CREATE TRIGGER trg_cash_ledger_entries_no_update BEFORE UPDATE ON cash_ledger_entries
    FOR EACH ROW EXECUTE FUNCTION prevent_append_only_mutation();
CREATE TRIGGER trg_cash_ledger_entries_no_delete BEFORE DELETE ON cash_ledger_entries
    FOR EACH ROW EXECUTE FUNCTION prevent_append_only_mutation();
CREATE TRIGGER trg_cash_ledger_entries_no_truncate BEFORE TRUNCATE ON cash_ledger_entries
    FOR EACH STATEMENT EXECUTE FUNCTION prevent_append_only_mutation();
```
Reversal validator skeleton (V15 `validate_cash_ledger_reversal`): `IF NEW.reversal_of_id IS NULL THEN RETURN NEW;` → `SELECT * INTO original ... WHERE id = NEW.reversal_of_id` → checks (exists / same user / not itself reversal / mirror fields) each `RAISE EXCEPTION '<static msg>' USING ERRCODE = 'check_violation'`. Static messages, no field values. "Only once" left to `UNIQUE (reversal_of_id)`. Per RESEARCH Q1.3 / Pitfall 5, reversal rows carry the **same** (positive) values; aggregations must use `case when reversal_of_id is null then x else -x end`.
Header comment style: Chinese block explaining why / version-number note (V15 L1-15).

## Shared Patterns

### Idempotent append-only write (backend)
Source: `CashLedgerService.createEntry` L106-160 + `JdbcCashLedgerRepository.insertIfAbsent` L66-88 + V15 constraints. Apply to dividend + share-adjustment writes. Never catch unique-violation then re-read inside the tx.

### Auth / authorization
Source: `CashLedgerController` — `@PreAuthorize("hasAuthority('…')")` on every endpoint (ArchUnit-enforced), `AuthenticatedUserResolver.resolve(authentication)`. Writes `TRADE_EXECUTE`, reads `PORTFOLIO_VIEW`, watchlists `WATCHLIST_MANAGE`.

### Audit
Source: `CashLedgerController` L66-77 — `auditLogger.log(userId, action, "<res>:" + id, "success", ip)` / `"failure:" + code`, rethrow.

`FieldValidationException(staticMsg, Map.of(field, reason))` → 400 `VALIDATION_FAILED` with `fields`; static messages, no echo of input.

### Cache invalidation
`PortfolioCache.invalidateAfterTrade` / `invalidateSummaryAfterCommit` (after-commit, only on real insert).

### Frontend transport
Only `apiRequest` / `apiPaginatedRequest` from `FE: src/services/apiClient.ts` (L328, L352). WS ticket must also go through `apiRequest` (POST `/api/v1/market/ws/ticket`).
