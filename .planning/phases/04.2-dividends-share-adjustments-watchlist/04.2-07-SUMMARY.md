## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `ck_share_adjustments_shape` 放行缺比例的 SPLIT**
- **Found during:** Task 1（本機 PostgreSQL 驗 V17）
- **Issue:** plan 給的 `(type='STOCK_DIVIDEND' AND …) OR (type='SPLIT' AND ratio_new > 0 AND ratio_old > 0 AND …)` 在 `ratio_old` 為 NULL 時，第二支得 NULL、整式為 `false OR NULL = NULL`，CHECK 把 NULL 視為通過 → 缺比例的 SPLIT 被寫入。另外 PostgreSQL 依約束名稱字母序檢查 CHECK（`…_shape` 先於 `…_type`），`'DIV'` 會被報成 shape 違規，Task 2 要求的「`ck_share_adjustments_type` 拒絕 'DIV'」無法成立。
- **Fix:** 改寫為 `CASE type WHEN 'STOCK_DIVIDEND' THEN … WHEN 'SPLIT' THEN ratio_new IS NOT NULL AND ratio_old IS NOT NULL AND … ELSE TRUE END`；未知 type 交給 `ck_share_adjustments_type`。語意與 plan 的意圖相同、約束名稱不變。檔內註解寫明兩個理由；IT `splitWithoutRatioIsRejected`、`unknownTypeIsRejected` 釘住。
- **Files modified:** V17__share_adjustments.sql
- **Commit:** `b4c007d`

**2. [契約優先] SPLIT 缺比例的 fields 鍵**
- plan Unit 5 寫「SPLIT 缺 ratio 或 ratioNew == ratioOld → fields.ratio」；凍結契約〈錯誤〉列的是 `ratio`（相等）/ `ratioNew` / `ratioOld`。依契約：缺 ratioNew → `fields.ratioNew`、缺 ratioOld → `fields.ratioOld`、相等 → `fields.ratio`（與 bean validation 範圍違規的鍵一致）。

**3. Commit scope**：plan 寫 `feat(db)` / `feat(trading)` / `test(start)`；依 orchestrator 指示用 `04.2-07`。

**4. IT 拆分**：plan IT 3 的「無持倉 409」與「CSRF 403」拆成兩個 `@Test`（`ShareAdjustmentApiIT` 共 4 個）；Task 2 另加生效瞬間不符、type 不符、合股負 ΔQ 可寫入等案例（22 個 ≥ 15）。
