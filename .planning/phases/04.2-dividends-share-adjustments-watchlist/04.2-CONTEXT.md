## Phase Boundary

1. **股利與股數調整**:現金股利、配股(股票股利)、拆股 / 合股的記錄,影響現金、股利收入、持股數與平均成本。

<decisions>
## Implementation Decisions

### 現金股利
- **D-01:** 會計:金額記入**該標的幣別現金** + 計為**股利收入**;**不動**股數與平均成本。summary 另列股利收入並計入總損益(國際券商標準做法)。
- **D-02:** 輸入:標的、日期、**實領總額**(標的幣別)、**預扣稅**(選填)。不做「每股配息 × 持股」的系統計算。
- **D-03:** 持倉已賣光或從未持有時**仍可記**現金股利(除息前賣出、之後才入帳很常見)。

### 配股(股票股利)
- **D-04:** 本 phase 一起做(Yuan 決定,推翻「列 Deferred」建議)。
- **D-05:** 輸入**實領股數**;總成本不變、平均成本攤薄(例:1000 股均價 100,配 50 股 → 1050 股,均價約 95.24,總成本仍 100,000)。
- **D-06:** 必須有持倉,否則拒絕。

### 拆股 / 合股
- **D-07:** 本 phase 一起做(Yuan 決定)。與配股同一套「股數變、總成本不變」計算,設計成可重用。
- **D-08:** 輸入**比例**(例 `4:1`、`1:10`),依事件日持股計算新股數;合股產生的零股以小數保留(持股本為 8 位小數)。
- **D-09:** 必須有持倉,否則拒絕。
- **D-10:** 拆股 / 配股當日的今日損益:前收依比例調整後再比較,避免價格斷層被算成當日大跌(04.1 今日損益需留好擴充點)。

### 記錄入口與顯示
- **D-11:** 前端入口:**Positions 每檔持倉**開對話框,標的預填;與下單 ticket 分開(這些都不是「下單」)。名稱為 **「股利與股數調整」**(Yuan:不要叫「公司行動」)。無持倉時記現金股利的入口由 UI 階段決定(D-03)。
- **D-12:** Trades 頁籤:「股利」= 現金股利;新增「股數調整」頁籤放配股 / 拆股;「全部」照常顯示所有類型。
- **D-13:** 資料維持 append-only(比照 `transactions`);記錯以沖銷修正。是否擴充 `transactions`(目前 `ck_transactions_type` 只允許 BUY / SELL、quantity / price 必須 > 0)或新開事件表,由研究 / 規劃決定並說明取捨。

### Watchlist
- **D-14:** **多個具名清單**(對齊前端 mock,Yuan 選擇多於建議的單一清單)。
- **D-15:** 清單操作:建立、改名、刪除、清單內排序(mock 原本沒有改名 / 刪除)。
- **D-16:** Chart / Markets 的星號:**點擊跳出清單選擇**,可指定加到哪個清單(與 mock「加到第一個清單」不同,需新 UI)。
- **D-17:** 首次需要時後端自動建立預設清單「我的自選」;上限每人 **20** 個清單、每清單 **100** 檔,超過回 `VALIDATION_FAILED`。
- **D-18:** 可加入**所有 active 資產**(含 FX / 債券,非 tradeable 也可);沒有行情的標的報價顯示「—」。
- **D-19:** 清單 API **一併回傳報價**,沿用 `MarketDataFacade.findDailyQuotes`(報價卡同一套交易日定義),一個請求拿完;即時價由前端 WS 訂閱更新。
- **D-20:** PROJECT.md Out of Scope 的「watchlists 延後」需移除 / 改寫;需求屬 PORT-06 的 watchlist 部分提前。
