## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline status-dot gaps, segmented-control internal gaps, metadata rows |
| sm | 8px | Button icon/text gaps, compact row spacing, session indicator gaps |
| md | 16px | Auth form field gaps, banner body spacing, default panel padding |
| lg | 24px | Page padding, modal/header padding, auth panel vertical grouping |
| xl | 32px | Separation between auth form sections and session diagnostics |
| 2xl | 48px | Dedicated anonymous/auth view vertical breathing room inside app shell |
| 3xl | 64px | Reserved for full-page empty state only; avoid in normal auth surfaces |

Exceptions: preserve existing `Header.vue` dimensions (`60px` height, `22px` horizontal padding, `32px` avatar, `36px` icon button) and existing overlay offsets (`Toast` bottom `24px`, `TweaksPanel` bottom/right `16px`). New auth controls must use stable dimensions: inputs `36px` min-height, primary buttons `36px` min-height, icon-only targets `36px` minimum and `44px` when used as a touch-only close/action target.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 400 | 1.45 |
| Label | 12px | 400 | 1.35 |
| Heading | 16px | 600 | 1.35 |
| Display | 20px | 600 | 1.25 |

Constraints:

- Use only these four sizes for new Phase 2 auth/session UI.
- Use only two weights for new text: `400` and `600`. Existing local `500` button/label styles may remain, but new auth components should use `600` for emphasis instead of adding intermediate weights.
- Letter spacing must be `0` in new Phase 2 UI. Existing brand and uppercase micro-label letter spacing may remain.
- Error details containing `error.code`, HTTP status, or `meta.traceId` must wrap within the panel; never truncate trace IDs in a way that prevents debugging.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` (`#fafaf9` light, `#0c0d10` dark) | App background and page-level shell |
| Secondary (30%) | `var(--surface)` / `var(--surface2)` | Header, auth panel, session banner, form controls, popovers |
| Accent (10%) | `var(--accent)` default `#ff6600` | Primary auth action, focused input border, authenticated/session-ready dot, active auth tab |
| Destructive | `var(--dn)` default `#dc2626` | Logout, expired session, CSRF failure, invalid runtime mode, auth failure emphasis |

Accent reserved for: `登入` / `Sign in` primary CTA, active `登入`/`建立帳號` segmented tab, input focus border, authenticated/session-ready status dot, retry action when the session can recover. Do not use accent for every link, all banners, generic notification counts, or diagnostic text.

Secondary semantic colors:

- `var(--up)` may be used only for successful authenticated/session-ready status if a green success indicator is already used nearby.
- `var(--dn)` must be used for destructive or security-failure emphasis, paired with text and not relied on alone.

## Interaction Contract

### Required Session States

| State | Trigger | Required UI behavior |
|-------|---------|----------------------|
| `checking` | API mode app boot before `/api/v1/me` resolves | Show compact session banner/status text; do not show stale authenticated identity; keep existing page shell mounted |
| `authenticated` | `/api/v1/me`, login, or register succeeds | Show user email/username in header session area; enable logout; clear auth errors |
| `anonymous` | `/api/v1/me` returns 401, logout succeeds, or refresh is unavailable | Show login/register entry point inside app shell; hide authenticated-only identity |
| `refreshing` | `apiClient.ts` handles one 401 refresh/replay | Disable duplicate login/logout/unsafe actions that depend on session; keep current page visible with pending session status |
| `error` | Backend outage, CSRF bootstrap failure, invalid runtime mode, refresh failure, malformed auth envelope | Show global session banner and actionable retry/sign-in path; never silently fall back to mock in API mode |

### Auth Placement

- Mount auth/session UI in the existing product shell, preferably through `App.vue` plus a focused `AuthPanel.vue` or equivalent shell-mounted component.
- Do not create a landing page, hero, marketing section, decorative illustration, or full redesign.
- Use a constrained auth panel width of `360px` to `420px`; max width `calc(100vw - 32px)` on mobile.
- Use one panel only. Do not put cards inside cards. A modal is acceptable for logout confirmation; a route-level auth panel is acceptable for anonymous state.
- Keep a compact session indicator near the existing header avatar/search area. Maintain header height at `60px`; status changes must not shift nav layout.

### Forms

- Login fields: visible labels for email and password, `autocomplete="email"` and `autocomplete="current-password"`.
- Register fields: visible labels for email, username/display name if required by backend, password, and confirm password only if implemented locally.
- Submit buttons must disable while in flight and keep stable width/height.
- Field-level validation may appear under inputs in 12px text; session-wide failures use the global banner or inline panel above the form.
- Do not display access tokens, refresh tokens, cookie values, `Set-Cookie`, Redis keys, or internal session IDs in any form, toast, debug row, or local/session storage.

### Global Session Banner And Toast

- Use toast only for short non-blocking events: successful logout, successful login/register if the page already visibly changes, or copied diagnostic ID.
- Use a persistent inline/global session banner for blocking or security-related failures: 401 after refresh failure, `AUTH_CSRF_TOKEN_INVALID`, `AUTH_REDIS_UNAVAILABLE`, backend unreachable, invalid runtime mode, malformed auth envelope.
- Banner layout: `var(--surface)` background, `1px solid var(--border)` for neutral/checking, destructive tinted border/background for security failure, `8px` radius, `12px 14px` padding, icon/status dot plus text.
- Banner actions: `重試` / `Retry` for CSRF/backend outage/session restore; `重新登入` / `Sign in again` for expired session; no action for invalid runtime mode except diagnostic text.

### Header Session Indicator

- Anonymous: text `尚未登入` / `Signed out`, muted dot, visible `登入` action.
- Checking/refreshing: text state plus neutral pending dot; no spinner-only status.
- Authenticated: user email or username, session-valid dot, logout affordance.
- Error: destructive dot plus short label; details remain in global banner, not squeezed into header.
- Header avatar remains `32px`; if user initials are used, derive from safe user metadata only.

### Runtime Mode Visibility

- Mock mode may keep current app behavior, but API mode must make session state visible.
- Explicit invalid `VITE_DATA_MODE` must render an app-level error state rather than showing mock data.
- API-mode backend outage must show backend unavailable copy and retry; existing mock portfolio/trading content must not be presented as if it came from API mode.

### Unsafe Actions And CSRF

- Unsafe auth actions in this phase are register, login, refresh, and logout.
- Submit buttons must be disabled while request is in flight.
- Before unsafe API-mode requests, UI state may show `checking`/`refreshing`; it must not invite repeated clicks.
- On `AUTH_CSRF_TOKEN_INVALID`, show CSRF copy, include `AUTH_CSRF_TOKEN_INVALID` in details, and offer refresh/retry. Do not describe CSRF as optional or user-configurable.

## Layout Contract

| Surface | Layout requirement |
|---------|--------------------|
| Auth panel | `360px`-`420px` constrained panel, `24px` padding desktop, `16px` mobile, one panel only |
| Auth tabs | Segmented control style matching `Settings.vue` `.seg-pill`; `登入` and `建立帳號` labels fit without wrapping at 320px viewport |
| Global session banner | Full-width within current content column or fixed shell row below header; must not cover header/nav |
| Header indicator | Inline near avatar/search controls; fixed height inside existing `60px` header |
| Logout confirmation | Existing modal pattern: centered, `min(420px, 92vw)`, explicit cancel and destructive confirm |
| Error details | Subdued details row below headline/body; wraps long trace IDs |

Responsive rules:

- At viewport widths below `760px`, header session indicator may collapse to status dot plus short label, with full details in the banner/auth panel.
- Auth panel must stay reachable without horizontal scrolling.
- Buttons and segmented controls must keep text inside their bounds in both `zh` and `en`.

---

## Accessibility Contract

- Every input has a visible `<label>`.
- Use `aria-live="polite"` for checking/authenticated/anonymous state changes and `aria-live="assertive"` for expired session, CSRF failure, backend outage, and invalid runtime mode.
- Focus must move to the auth panel heading after session expiry redirects the user to anonymous/login state.
- Focus states must be visible on inputs, segmented tabs, primary/ghost buttons, retry actions, and logout confirmation controls.
- Loading states require text (`正在確認登入狀態...`, `正在更新登入狀態...`), not only animation.
- Error text cannot rely on color alone; include plain-language message plus code/details.

---

## Security Display Contract

The UI must never display or persist:

- Access token values.
- Refresh token values.
- `stock_access` or `stock_refresh` cookie values.
- Raw `Set-Cookie` headers.
- Redis keys, refresh-token hashes, internal session IDs.
- Password values outside password inputs.

The UI may display:

- User email, username, role, and status returned by `/api/v1/me`.
- Expiry timestamps returned as session metadata, if shown as non-sensitive diagnostics.
- Backend `error.code`.
- HTTP status.
- Backend `meta.traceId` or legacy request id.
- Safe cookie/header names `XSRF-TOKEN` and `X-XSRF-TOKEN` only in developer-oriented documentation or diagnostics, not as normal user instructions.
