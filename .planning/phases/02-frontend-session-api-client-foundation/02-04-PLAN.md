<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Session model -> visible UI | Safe metadata and error diagnostics become user-visible. |
| User input -> auth endpoints | Login/register form input crosses into backend auth API. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Information Disclosure | auth/session components | mitigate | Tests forbid rendering tokens, cookie values, `Set-Cookie`, internal session IDs, or password values. |
| T-02-13 | Spoofing | Header session indicator | mitigate | Header receives session state from `authSession`; stale identity is hidden when state is not authenticated. |
| T-02-14 | Tampering | repeated unsafe auth actions | mitigate | Auth panel disables submit/logout while requests are in flight or session is refreshing. |
| T-02-15 | Repudiation | user-visible errors | mitigate | Banner shows safe user copy plus code/status/requestId details for debugging. |
| T-02-SC | Tampering | npm installs | accept | No package-manager install is planned; UI uses existing Vue/CSS only. |
</threat_model>
