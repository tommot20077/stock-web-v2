<objective>
把 V10 的資料庫約束接上領域層與資料存取層：`TradeTransaction` 帶得動 `idempotencyKey`，`JdbcTradingRepository` 具備「以 key 查既有交易」與「帶 key 的冪等 insert」兩個能力。

Purpose：04-03 的 `TradingService` 冪等分支需要這兩個 repository 方法才寫得出來，而它們的正確性（特別是 partial index 的 `ON CONFLICT` 推斷）**只能**用真實 PostgreSQL 證明。本 plan 把「SQL 能不能推斷成功」與「service 的流程對不對」分開，讓 04-03 的失敗一定是流程問題而不是 SQL 問題。

Output：`TradeTransaction.idempotencyKey`、`TradingRepository.findByIdempotencyKey`、`TradingRepository.insertTransactionIfAbsent`、擴充後的 `TransactionsIdempotencyIT`。

**本 plan 不改 `TradingService.createTrade` 的流程順序** —— 它只做「因 record 多一個 component 而必須改的呼叫端修正」（傳 `null`），冪等分支是 04-03 的工作。
</objective>
