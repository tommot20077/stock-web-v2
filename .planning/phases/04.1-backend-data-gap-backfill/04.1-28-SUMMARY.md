# 04.1-28 — C1 旅程缺少「切到 Settings 顯示分頁」一步(gap-closure)

## 發現

後端 PR #50 的 CI `Browser E2E Tests`(run 40151110586,head 1877470)是 04.1-20 三條真後端旅程
**第一次實跑**。42 條中 41 通過,僅 `cash-journey.spec.ts:52` **C1** 失敗(首跑與 retry 皆失敗,
非 flaky):

```
expect(page.getByTestId('settings-base-currency')).toHaveValue('USD')  → element(s) not found
```

## 根因(測試缺陷,非實作缺陷)

`Settings.vue` 預設開在 `brokers` 分頁(`const tab = ref('brokers')`),基準幣下拉位於 `display` 分頁。
C1 點 `nav-settings` 後直接找下拉,元素永遠不在 DOM。證據:

- C1 在該步之前的斷言(Overview 切 USD、`/me.baseCurrency === 'USD'`)全數通過 → 持久化路徑正常。
- C2、C3 通過 → 入金、沖銷、未入金買進美股在真後端正常。
- 元件測試 `Settings.test.ts` 用 `openDisplayTab()` 先切分頁,所以本機單元測試沒有露出此問題;
  本機也沒有 Docker 跑不了該旅程 → 04.1-20 SUMMARY 已誠實標示「旅程待 CI 證明」。

## 修正

- RED `test(04.1-28)`:`Settings.test.ts` 新增「每個分頁按鈕有 `settings-tab-<key>`,預設畫面沒有基準幣下拉,
  點 `settings-tab-display` 後才出現」;失敗原因為分頁按鈕沒有 testid。
- GREEN `fix(04.1-28)`:`Settings.vue` 分頁按鈕加 `data-testid="settings-tab-${k}"`;
  `cash-journey.spec.ts` C1 在斷言前先 `click settings-tab-display`;`e2e/support/selectors.md` 補 `settings-` 前綴。
- 沒有放寬、跳過或刪除任何斷言(C1 的 `toHaveValue('USD')` 與跨 context 反向斷言原樣保留)。
