## Pattern Assignments

### `V15__cash_ledger_entries.sql`(migration)

**Analog:** `BE stock-db-migration/src/main/resources/db/migration/V8__transactions_append_only_trigger.sql`(全檔 26 行)
```sql
CREATE OR REPLACE FUNCTION prevent_transactions_mutation()
    RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    RAISE EXCEPTION 'transactions is append-only: % is not permitted', TG_OP
        USING ERRCODE = 'restrict_violation';
END;
$$;
CREATE TRIGGER trg_transactions_no_update  BEFORE UPDATE  ON transactions FOR EACH ROW EXECUTE FUNCTION prevent_transactions_mutation();
CREATE TRIGGER trg_transactions_no_delete  BEFORE DELETE  ON transactions FOR EACH ROW EXECUTE FUNCTION prevent_transactions_mutation();
CREATE TRIGGER trg_transactions_no_truncate BEFORE TRUNCATE ON transactions FOR EACH STATEMENT EXECUTE FUNCTION prevent_transactions_mutation();
```
- V8 訊息寫死表名、已套用不可改 → 新寫通用 `prevent_append_only_mutation()` 用 `TG_TABLE_NAME`(RESEARCH Q6.2 草稿)。
- 表結構照 RESEARCH Q6.2 草稿,**另加** D-25:`reversal_of_id BIGINT NULL REFERENCES cash_ledger_entries(id)`、`UNIQUE (reversal_of_id)`(擋重複沖銷),並以 BEFORE INSERT trigger 驗證「原分錄非沖銷分錄、幣別與金額一致、type 相反、同 user」。
- 冪等索引:新表無舊資料 → `NOT NULL` + 一般 `UNIQUE (user_id, idempotency_key)`,不要抄 V11 的 partial predicate(V11 :40、:54-56)。
- 版號:目前最大 V13,V14/V15 撞號見 RESEARCH Pitfall 7。
