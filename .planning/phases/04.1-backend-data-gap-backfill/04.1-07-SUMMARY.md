# Phase 04.1 Plan 07: 今日價格損益（單檔與總額）Summary

## 恆等式與 D-26 的數學說明

設 Q0 = 交易日起點持股、B/pb = 今日買入、S/ps = 今日賣出、Q1 = 目前持股 = Q0 + ΣB − ΣS、L = 最新價、C = 前收。

D-12 三段：`(Q0 − ΣS)(L − C) + ΣB(L − pb) + ΣS(ps − C)`。展開：

```
= Q0·L − Q0·C − ΣS·L + ΣS·C + ΣB·L − ΣB·pb + ΣS·ps − ΣS·C
= (Q0 − ΣS + ΣB)·L − Q0·C − ΣB·pb + ΣS·ps
= Q1·L − Q0·C − ΣB·pb + ΣS·ps
```

`Q0 − ΣS` 為負（今天買的也被賣掉）時代數同樣成立；右式不必決定賣掉的是哪一批，所以當沖與全數平倉自然正確。Q0 由 `Q1 − ΣB + ΣS` 反推，**不需要日級快照表**（回答 todo `2026-07-19-backend-daily-pnl.md`）。

**D-26 的依據：C 的係數只有 −Q0。** Q0 = 0（今天才首次買入，或當日買賣來回後歸零）時 C 不參與計算，所以沒有前收也算得出來，分母 `Q0·C + ΣB·pb` 退化為買入成本。只有 Q0 > 0 而前收缺失才回 empty；最新價 L 一律必要；Q0 < 0（補登造成的時序矛盾）回 empty、不硬算。不扣手續費（D-15），與已實現損益會扣 fee 的語意不同。

## null / 0 規則

| 層級 | 情形 | 結果 |
|------|------|------|
| 單檔 | 無行情 | `previousClose` / `dayPricePnl` / `dayPricePnlRatio` / `dayPnlBasis` 皆 null，市值沿用均價估值 |
| 單檔 | Q0 > 0 且無前收 | 損益與比率 null，`previousClose` null |
| 單檔 | Q0 = 0（今天首次買入 / 當沖） | 照算，不回 null |
| 單檔 | 分母為 0 | 損益照給，比率 null |
| summary | 沒有任何候選（無持倉且今日無成交） | `dayPricePnl = 0`、ratio null、excluded 0 |
| summary | 有候選但全部被排除（或全換不到匯率） | `dayPricePnl = null`、ratio null |
| summary | 其餘 | Σ（基準幣，目前匯率）；ratio = Σ損益 / Σ分母（scale 8），分母為 0 時 null |

`dayPnlExcludedCount` 只計「價格缺失」的候選；換不到匯率者計入 `fxExcludedCount` / `unconvertedCurrencies`（D-04），不重複計入此數。

## 7 天平倉候選邊界

平倉列（`total_quantity = 0`）只有 `last_updated >= now − 7 天` 才進入候選（賣出會以現在更新 `last_updated`）；進入候選後還要「今天有成交」才算候選，沒有今日成交的平倉列不算排除也不影響 0 / null 判斷。平倉列有行情時 dayStart 取自 quote，無行情時取 `tradingDay.dayStart(Instant.now())`。已知限制：某市場連續 7 天以上沒有任何 tick 時，交易日起點更早，邊界外的賣出不計入。

## 給 Phase 04.2 的擴充點（必讀）

`DayPnlCalculator.calculate(quantityNow, latestPrice, previousClose, fills, List<ShareAdjustment> adjustments)` 的最後一個參數就是拆股 / 配股擴充點。04.2 實作拆股時：

1. 取得該標的「本交易日」的非現金股數變動（拆股當日多出的股數 = `Q0×(r−1)`），包成 `new ShareAdjustment(quantityDelta)`。
2. 在 `PortfolioQueryService#calculateAndCacheHolding`（持倉列）與 `#dayTotals`（平倉候選）兩處把目前的 `List.of()` 換成該 list。
3. 計算器內 `Q0 = Q1 − ΣB + ΣS − Σ(quantityDelta)`，**C 不調整**：此時 `Q0(拆前股數) × C(拆前前收)` 即前收時市值，與 04.2 D-10「前收依比例調整」數值相同；若不扣除，拆前價乘上拆後股數會被算成暴漲暴跌。
4. 單元測試 `shareAdjustmentIsSubtractedFromOpeningQuantity` 已固定此語意。`HoldingDto.previousClose` 目前回原值，04.2 若要顯示「調整後前收」需另行處理。
