# Phase 04.1 Plan 29: 後端 REST 層 E2E 補齊 Summary

**起因：Yuan 駁回 04.1-25 第 14 項的 E2E 層豁免（「不接受,要補」）。testing-standards 規定 Unit / Integration / E2E 三層缺一不可，
Phase 04.1 新增的端點只有 Unit 與 `*IT`，瀏覽器旅程（cash-journey.spec.ts）不能取代後端 REST 層 `*E2E`。
本 plan 新增 4 個 `*E2E` 類別共 33 個測試，走真實 Spring 應用 + 真實 Postgres / Redis，由 `AuthE2EHelper` 取得 bearer 身分。**

## 重要：本機未執行（CI-only）

`-Pe2e` 的 `AbstractStockE2ETest` → `ContainerIT` 以 Testcontainers 啟動 TimescaleDB、Redis、Kafka。本環境
`docker ps` 回 `failed to connect to the docker API`；本機雖有 PostgreSQL 16 與 redis-server 執行檔，但沒有 TimescaleDB 擴充
（V4 / V5 migration 需要 hypertable / continuous aggregate）也沒有 Kafka，而 `ContainerIT` 不能繞過，故**這 33 個測試沒有在本機跑過，
不宣稱通過**。證據只有編譯與格式；執行證據待 CI `E2E Tests` job（`./mvnw -B -pl stock-start -am test -Pe2e`，
`**/*E2E.java`；預設 surefire 已排除 `**/*E2E.java`，故不會誤入 Unit job）。

- **Found during:** 閱讀既有 E2E support 時
- **Issue:** 清理只刪 transactions / holdings / backtest_runs / users；V15 的 `cash_ledger_entries.user_id` 有 FK 指向 users，且表上有禁止 DELETE 的 trigger。新測試會留下現金分錄，若不清，輕則殘留孤兒列，重則（未在 replica 角色下）刪 users 被 FK 擋。
- **Fix:** 在既有 `session_replication_role = 'replica'` 區塊內、`DELETE FROM users` 之前補 `DELETE FROM cash_ledger_entries;`，並更新 Javadoc。
- **Files modified:** `stock-start/src/test/java/dowob/xyz/stockwebv2/start/e2e/support/DatabaseCleaner.java`（plan 範圍外但為讓新 E2E 可清理所必需）

## 未解與風險

- 33 個測試待 CI `E2E Tests` job 首次實跑（04.1-26 的教訓：CI 首跑才抓得到缺陷）。
- `AbstractPortfolioE2ETest` 的 `@AfterEach` 為 `protected` 以確保跨 package 繼承時被 JUnit 執行。
- 行情種子使用 TSLA / MSFT / META / AMZN / 2330.TW；每個測試結束刪除自己種的 `market_prices`，E2E 套件內其他類別（Asset / Backtest）不依賴這些資產的行情。
- 以 `occurredAt = 2026-10-0x` 的固定日期（與既有 `CashEntryApiIT` 相同）：CI 時鐘早於這些日期才會被「不得為未來」擋下，目前不是風險。
