## Idempotency-Key 處置表的實作對照

| 情境 | 實作 | 測試 |
|------|------|------|
| 首次送出 | `ensureIdempotencyKey()` → `crypto.randomUUID()`;開啟對話框不預先產生 | `opening the dialog does not mint a key…` |
| 網路失敗 / 5xx | 保留(`handleSubmitFailure` 預設不動 key) | `keepsTheKeyAfterANetworkFailure` / `keepsTheKeyAfterA5xx` |
| 改任一欄位 | `watch([type,currency,amount,occurredAt,note], …, { flush:'sync' })` 標 dirty,並清 `submitError` | `mintsANewKeyAfterAnyFieldChange`(改完立刻送出 → 本次就換 key) |
| `CASH_IDEMPOTENCY_KEY_REUSED` | 丟棄 | `dropsTheKeyAfterCashIdempotencyKeyReused`(未改欄位再送 → 新 key) |
| `VALIDATION_FAILED` + fields | 保留;欄位級呈現,底部不重複;改欄位自動換 key | `showsFieldLevelErrorsUnderTheFieldAndNeverTheFieldValue` |
| 三個沖銷衝突碼 | 丟棄 + `lockedError` + emit `reversalConflict` | `locksTheDialogAndNotifiesTheOpenerOn …`(it.each ×3) |
| CSRF / 403 | 保留 | 錯誤分派 it.each |
| 401 | 不顯示、key 保留,交給全域 SessionBanner | `doesNotShowA401InsideTheDialog` |
| 連點 | `if (submitting.value) return;` + `:disabled="submitting"` | `doubleClickSubmitsOnlyOnce` / `freezesTheWholeDialogWhileSubmitting` |

reversal 模式的備註變更同樣標 dirty(`mintsANewKeyAfterEditingTheNoteInReversalMode`:`['key-1','key-1','key-2']`)。

## 其他實作要點

- **前端自檢**:金額須匹配 `^(\d+\.?\d*|\.\d+)$`、≤ 8 位小數、> 0、≤ 1e12(與 `cashErrAmount` 靜態文案一致);發生時間不可晚於現在(送出當下以 `Date.now()` 重驗,避免開太久的舊 `max`)。空金額在 blur 前不顯示欄位錯誤,但常駐的 `cashAmountHint` 就是可見原因。
- **DOM 洩漏守門**:canary 斷言後端 `error.message`、`fields` 的 value、idempotency key(`key-1`)、原紀錄 id(`e-9`)都不在 DOM。
- **出金超額**:`balances.find(b => b.currency === currency)?.amount ?? 0` 只比較大小;未傳 `balances`、入金、剛好等於餘額、沖銷模式皆不顯示。
- **版面**:面板 480px / `92vw`、`max-height: calc(100vh - 48px)`、`.hd`/`.ft` `flex: none`、`.body` 內捲;`.btn-submit { min-width: 176px }`(en `Record withdrawal` 最寬),`< 400px` 時 footer 與 `.btn-accent` 水平內距 16px、min-width 160px;reduced-motion 停用 rise/fade/pop;所有新控件有 `:focus-visible` outline。
- UI-SPEC 複查:`padding/margin/gap` 的 px 值全在 {4, 8, 12, 16, 20, 24, 32, 48};`font-size` 僅 12/13/16/20、`font-weight` 僅 400/600(grep 逐行核對)。
