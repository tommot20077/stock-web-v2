<decisions>
## Implementation Decisions

### 範圍定性(judgment §1)
- **D-01:** 現金帳仍是**記帳**,不是券商帳戶:不驗證餘額、不擋交易、沒有撮合或凍結資金。這是對 Phase 4 留下的「現金是否讓語意偏向帳戶系統」疑問的正式回答。PROJECT.md Key Decisions 需補記此點。

### 基準幣與匯率
- **D-02:** 使用者基準幣存在**後端使用者設定**:`users` 加 `base_currency`(預設 `TWD`),`/api/v1/me` 回傳,可經 API 修改。
- **D-03:** 前端**兩處都能改**:Overview KPI 區的幣別快速切換(改完即寫回後端並重讀)+ Settings 頁的正式欄位(Settings 其餘仍是 mock,保留示範資料標示,只有這欄是真的)。
- **D-04:** 匯率讀既有 `fx_rates` 表(目前為 V2 seed 的靜態值:USD/TWD、TWD/USD、EUR/USD、USD/JPY)。沒有直接匯率時**經 USD 三角換算**;仍換不到的部位**不計入**基準幣總額,並回傳「N 檔因缺匯率未計入」讓前端提示。
- **D-05:** 既有 `PortfolioSummaryDto` 的金額欄位改為**以基準幣表示**,並新增 `baseCurrency` 欄位。這是契約語意變更(修正錯誤的跨幣別相加),必須同步更新 `ai-docs/trading-portfolio-contract.md` 與前端型別 / 顯示。

### 可用現金
- **D-06:** 手動現金帳:使用者記入金 / 出金;買入自動扣(數量 × 價格 + 手續費)、賣出自動加(數量 × 價格 − 手續費)。
- **D-07:** 現金**依幣別分開**記餘額(USD 現金、TWD 現金…);交易的現金異動用該標的的幣別。Overview 顯示時再折算基準幣(D-04)。
- **D-08:** 現金**允許為負**,畫面提示(例:「可能少記了入金」)。不擋交易。
- **D-09:** 入金 / 出金 **append-only**,記錯以**沖銷分錄**修正,不可修改 / 刪除(與 `transactions` 一致,DB 層同樣保護)。
- **D-10:** 餘額**一律從分錄即時推導**(入出金合計 ± 全部既有交易),不另存餘額欄位;功能上線前的既有交易也計入(會讓舊資料現金為負,由 D-08 的提示引導補記入金)。
- **D-11:** 入出金 UI:Overview「可用現金」卡片上的「入金 / 出金」按鈕,開一個與下單 ticket 同風格的小對話框;沿用 `Idempotency-Key` 與成功後重讀(Phase 4 D-14 模式)。

### 今日損益
- **D-12:** 券商標準算法:昨日即持有的部分 `qty × (最新價 − 前收)`;今日買入 `qty × (最新價 − 買價)`;今日賣出 `qty × (賣價 − 前收)`。
- **D-13:** 「今天」= 各檔**自己市場的最近交易日**,即報價卡同一套 `TradingDay` / `MarketDataFacade.findDailyQuotes`(前收 = 交易日起點前最後一筆,與 1D K 線前一根 close 同義)。總額 = 各持倉最近交易日損益的加總(Yahoo / 券商 App 做法)。
- **D-14:** 顯示於 **Overview KPI + 每筆持倉**:summary 回總額,`HoldingDto` 回單檔。
- **D-15:** 只算**價格損益**,一律用目前匯率折算基準幣,API 與畫面明確標示「不含匯差」。欄位命名預留拆分(如 `dayPricePnl`),將來補 `dayFxPnl` 不必改語意。(Yuan 問「好系統要不要給匯差 / 做選項」:專業平台是**拆價格 / 匯兌兩塊並列**而非切換選項;本 phase 先做價格,匯兌列 Deferred。)
- **D-16:** 今日 % 的分母 = **前收時的持倉市值**(今日買入的部位以買入成本計),與報價卡漲跌 % 同義。
- **D-17:** 沒有前收(新標的 / 行情剛開始收集)或沒有行情的持倉:單檔回 `null`,summary 排除並回傳「N 檔未計入」;**不塞 0**(與報價卡「不塞預設價」一致)。

### 資產配置與產業分組
- **D-18:** donut 分塊 = `asset_type`(股票 / 加密 / 債券 / 外匯)+ **現金**,全部折算基準幣;沒有持倉的類別不顯示;現金為負時不列入 donut 並提示。
- **D-19:** 產業分組直接用 `assets.sector` 原值(加密的 seed 已是 `Crypto`);`sector` 為 null 歸「未分類」。不引入 GICS。
- **D-20:** 新資產的 sector 沿用 migration seed 維護,本 phase **不做**資產管理介面(Yuan 問要不要做:只改 sector 是半套——系統連新增資產的介面都沒有;真正需求在接真實行情源時由行情商帶入。列 Deferred)。
- **D-21:** 分組由**後端計算**:summary 新增 allocation(類別 → 基準幣市值 / %),`HoldingDto` 新增 `assetType`、`sector`。匯率只在後端折算一次,前端不需要知道匯率。trading 取資產屬性一律走 `AssetFacade`,**不得** SQL JOIN `assets`(2026-09-02 架構審查 H-1 的教訓)。

### Summary 呈現
- **D-22:** 新增 `totalEquity` = 持倉市值 + 現金(基準幣)與 `cash`(基準幣合計);既有 `roi` **語意不變**(以持倉成本計的持倉報酬)。帳戶層級報酬率列 Deferred。

### Claude's Discretion
- 拆股當日若有持倉,前收需依比例調整後再算今日損益(本 phase 無拆股,04.2 引入拆股時一併處理;04.1 的今日損益計算要留好這個擴充點)。
- 現金分錄的資料表設計、今日損益的計算放在查詢時或快取(沿用 `PortfolioCache` 讀時計算 + commit 後失效模式)由研究 / 規劃決定。
- 入出金 API 的路徑與 DTO 命名。

## Existing Code Insights

### Reusable Assets
- `MarketDataFacade.findDailyQuotes(Map<Long, TradingDay>)`:一次批次拿最新價 + 前收 + 當日高低,今日損益直接用。
- `TradingDay.of(assetType, market)` / `TradingDayResolver`:各檔交易日。
- `PortfolioCache`:讀時計算 + commit 後失效的持倉快取,新欄位沿用。
- `fx_rates` 表(V1 schema、V2 seed):匯率來源,目前無讀者。
- `AssetFacade` / `AssetSummary`:已有 `assetType`、`market`;需確認是否帶 `sector`、`currency`(若無,擴充 facade 而非 JOIN)。
- 前端 `MockDataNotice`、Phase 4 的 ticket 對話框與 Idempotency-Key 產生 / 重送邏輯。

### Established Patterns
- append-only + DB trigger(`V8__transactions_append_only_trigger.sql`)——現金分錄比照。
- 冪等寫入:insert-first、`ON CONFLICT DO NOTHING` + Idempotency-Key(Phase 4)。
- 金額 `BigDecimal`,`@Digits` 上限;錯誤訊息靜態、`fields` 指名欄位。
- 批次讀取避免 N+1(`findLatestPrices`、`readHoldings` MGET)。

### Integration Points
- `TradingService.createTrade`:買賣後的現金異動(由分錄推導,可能不需寫入;由規劃決定)。
- `TradingService.summary` / `listHoldings`:新增欄位與基準幣折算。
- `AuthController#me` / `MeResponse`:加 `baseCurrency`;新增修改基準幣端點(需 `@PreAuthorize`,ArchUnit `EndpointAuthorizationRulesTest` 會檢查)。
- 注意:`PortfolioSummaryDto` 目前 7 欄全為未折算的跨幣別加總(`totalMarketValue` 等)——D-05 修正。
