## Top 3 Priority Fixes

1. **Trades (and any `.num` table) numbers merge at narrow widths.**
   - **Impact:** at 375/320px, `0.5` quantity and `60,000.00` price render as `0.560,000.00`, and `910.00` + `455,000` as `910.00455,000`. In a money table this can be misread, and the phase's own `.ccy-tag` widens the rows.
   - **Fix:** give right-aligned numeric `td`/`th` a left padding (`padding: 11px 0 11px 12px` or `min-width`) in `Trades.vue:594,600`, and the same for Overview's recent-trades table. This also fixes `0.00—` (fee jammed against note, `m11a-trades.png`).
2. **Cash page hides Amount at ≤375px.**
   - **Impact:** the 04.1-30 fix pins `.col-type` and `.col-note` to `min-width: 160px` and keeps the date `nowrap`. At 320 and 375 the viewport shows only Date and Type; Amount is clipped (`fix30/cash-375-zh.png` shows a lone "+1") and Status is out of reach. There is no scroll affordance.
   - **Fix:** below 640px, collapse each row to a stacked layout (date + type pill above, signed amount and status below) instead of a horizontally scrolling table. Alternatively make Amount the second column and sticky.
3. **Text contrast tokens.**
   - **Impact:** `--up` (#16a34a) on white is about 3.3:1 for the 12-13px ratio and P&L lines. White on `--accent` (#ff6600) is about 2.9:1 for the 13px/600 submit buttons. `.quote-lab` uses `--fg-mute`, which the spec forbids for hint text. Dark-theme `--dn` on `--surface` is about 3.7:1 for 12px field errors (code-derived).
   - **Fix:** add text-safe tokens (for example `--up-text: #15803d`, about 5.0:1; a darker accent for filled-button text or dark text on accent), switch `.quote-lab` to `--fg-dim`, and lighten `--dn` in dark mode.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

**Strengths**
- All contract strings exist in zh and en. `tf()` placeholder replacement is used in `Cash.vue`, `Overview.vue` and `CashEntryDialog.vue`.
- The forbidden vocabulary (帳戶餘額, 轉帳, 撥款, buying power, 凍結) does not appear in the added i18n lines (grep clean).
- Error copy follows the contract: "nothing was recorded", and only the network error says resubmitting will not duplicate.
- The ledger-only and irreversibility disclosures are persistent in the form (`m07a-deposit-form.png`).
- Empty states are actionable: `cashEntriesEmpty` + body + a "Record deposit" button.
- No `alert()`/`confirm()` calls.

**Findings**
- WARNING: the result step shows `發生時間` as the raw backend ISO string, `2026-10-26T12:32:00+08:00` (`CashEntryDialog.vue:227` renders `recorded?.occurredAt` directly; `m07b-deposit-result.png`). The reversal summary card and the Cash table both use `formatDateTime`/`fmtDateTime`, so the three surfaces disagree. Route it through `formatDateTime`.
- WARNING: the result step repeats the same string twice: header `.hd-ttl` "入金已記錄" and `<h2 class="result-ttl">` "入金已記錄" (`m07b`). It reads as a bug. The spec asks for a result `h2`, so either drop the header title in this step or change the header to a neutral label.
- WARNING (pre-existing, but sits in a block this phase edited): `Settings.vue:85` still has `sub="Decimal & thousand separators"` in English in the zh UI. The neighbouring theme/language rows use inline `lang === 'zh' ?` ternaries instead of i18n keys.
- INFO: single-word ghost buttons `入金` / `出金` / `完成` were accepted by the spec checker's FLAG.

### Pillar 2: Visuals (3/4)

**Strengths**
- The focal-point contract is met. Overview has a four-card Display band (`m05a-overview-api.png`). Cash has a single `h2`. Each dialog step has exactly one Display element: the amount input, the reversal preview, or the result title.
- The ✕ button has an `aria-label`, and the decorative ✓/⚠/↗ glyphs are `aria-hidden`.
- Neutral treatment for in/out and for reversed entries (strikethrough plus pill) is clear (`m08b-after-reversals.png`).
- The "未分類" sector sorts last in neutral grey (`m10a-positions.png`).
- The `.ccy-tag` approach keeps the numeric columns clean.

**Findings**
- WARNING: an empty bordered strip (about 32px) sits between the header and every page's content in API mode (visible in `m05a`, `m10a`, `m11a`, `m08b`, and at 320). It is the `.session-shell` / `SessionBanner` region rendering with no content when signed in. It predates 04.1 but is on every audited screen and pushes content down, so it should be hidden when the status is `authenticated`.
- WARNING: a zero value is styled as a gain. AAPL shows `0` / `+0.00%` in green in the Positions P&L cell (`m10c-positions-table.png`), and `fmtRatioPct(0)` yields `+0.00%`. Overview's `signTone` correctly neutralises zero, but the Positions holding cell does not. Treat zero as `--fg-dim` with no sign.
- WARNING: the Trades table has a `手續費備註` pair that reads as one header, with fee `0.00` touching note `—` as `0.00—` (`m11a-trades.png`). This is an alignment/spacing issue (see Pillar 5).
- WARNING (hierarchy): the reversal "原紀錄" label is grey `--fg-mute` and recedes more than its content (`m02d-reverse-dialog.png`). See Pillar 3.
- INFO: the sector bars are bare `div`s with no role or label. This is acceptable because the weight is repeated as text beneath.

### Pillar 3: Color (3/4)

**Strengths**
- No new colour variables. Accent is confined to the spec whitelist: dialog submit, focus rings, STOCK donut slice, sector[0] bar, weight bars, fresh highlight. Type and currency toggles are correctly neutral (`1px solid var(--fg)`), as is the base-currency switch. `--dn` is used only for errors and negative P&L.
- Negative cash is `--fg` plus a ⚠ and full text, not red.

**Findings**
- WARNING: `.quote-lab { color: var(--fg-mute) }` (`CashEntryDialog.vue:736`) violates the Typography constraint "hint text must be `--fg-dim`, never `--fg-mute`" (about 2.6:1). Dark-theme `--fg-mute` (#62605a) is about 2.7:1.
- WARNING: `--up` text is about 3.3:1 on white and lower on `--surface2`. It is used for 12-13px ratio and P&L lines (`Overview` `.kpi-s`, Positions P&L, sector P&L). The 20px KPI numbers stay `--fg`, as designed.
- WARNING: white 13px/600 label on `--accent` #ff6600 is about 2.9:1 (`.btn-accent` in the new dialog; the same inherited pattern exists in OrderTicket). It is spec-mandated, but it still fails AA.
- WARNING (code-derived, dark theme): `--dn` #dc2626 on dark `--surface` #15171c is about 3.7:1, below AA for 12px field errors. `.form-error` hard-codes `rgba(220,38,38,0.10)` instead of deriving from `--dn`.
- INFO: category colours are literal hex constants (spec-sanctioned). Allocation legend swatches are paired with text labels, so there is no colour-only meaning.

### Pillar 4: Typography (3/4)

**Mechanical check** (`grep font-size/font-weight` over `CashEntryDialog.vue` and `Cash.vue`): only 12/13/16/20px and 400/600 are used.
- Dialog: 9×12px, 7×13px, 2×16px, 4×20px.
- Cash page: 10×12px, 8×13px, 1×16px, 1×20px.
- The `.kpi-v` (26 to 20px) and `.ttl` (14 to 16px) migrations are done. `.kpi-v` has `letter-spacing: 0`.
- The diff against `develop` shows no new off-scale sizes in rewritten regions.

**Findings**
- WARNING: `Cash.vue:547` `h2 { letter-spacing: -0.4px }`. The spec says letter-spacing is always 0, and `.kpi-v`'s `-0.5px` was removed for the same reason.
- WARNING: on the same screens the grandfathered blocks still use 10px (`.news-tag`), 11px (`.pill`, `thead th`, `.stat-l`, watchlist sub-lines) and weight 500. The spec excluded them, but the result is six sizes and three weights per page next to the new 12/13/16/20 content. The "four sizes, two weights" claim holds only for new code.
- INFO: the Cash `h2` is 20px and sits against Positions' 22px `h2` and Trades' title in the same nav. This is an intentional spec choice, but page-title sizes now differ between Cash and its neighbours.

### Pillar 5: Spacing (3/4)

**Mechanical check** (spec command over the new files): all `padding`/`margin`/`gap` values are 4/8/12/16/20/24/32/48. Pill `padding: 0 8px; line-height: 1.2` matches the spec exception. Dialog geometry (`16px 24px` header, `24px` body, `48px 32px` result) matches the contract, and the `<400px` footer override is present.

**Findings**
- WARNING: the Trades table (`Trades.vue:594,600`: `thead th { padding: 10px 0 }`, `tbody td { padding: 11px 0 }`) has zero horizontal cell padding. The phase added `.ccy-tag` and `fmtMoneyAmount` to this table. At 375 and 320px it now yields `0.560,000.00` and `910.00455,000` (`m13-375-trades.png`, `m13-320-trades.png`), and the BUY pill touches the date. `10px` and `11px` are also off the scale (pre-existing, grandfathered).
- WARNING: on the Cash page at ≤375px the `min-width: 160px` pins on `.col-type`/`.col-note` consume the card width (see Experience Design).
- WARNING: off-scale or off-spec new values:
  - `Settings.vue` `.ccy-diag { gap: 4px 10px }` (10px is not on the scale).
  - Overview `.block-retry { min-height: 32px }`, versus 36px in Cash and Settings and in the spec.
  - Overview `.ccy-btn { border-radius: 4px }` versus 8px in the dialog's copy of the same `.ccy-seg` pattern.
- INFO: `.page { padding: 24px }` on Cash versus 22px on Overview, Positions, Trades and Settings gives a visible 2px title offset when switching tabs. It is spec-mandated (U-5), but it will look like a mistake.

### Pillar 6: Experience Design (3/4)

**Strengths**
- Every state in the spec's UI-Considerations table has code:
  - Cash entries: loading with skeleton, error with retry, empty with CTA, refreshing (`.block-refreshing` + note), stale with retry (`role="status"`), not-in-view hint, and pagination reset on cause `'cash'` only.
  - Summary: loading, error, refresh stale per cause.
  - Dialog: submitting guard (double check, disabled inputs, mask/✕/Esc blocked, `aria-busy`, `role="status"`), per-code error mapping, idempotency-key discard/keep rules, reversal-conflict lock with a persistent visible reason.
- Base-currency switch: four buttons disabled while switching, `role="status"` and `role="alert"`, rollback on failure, no confirmation dialog (reversible setting).
- Mock/API gating honours iron rules 3 and 6: deposit/withdraw buttons and the switch are not rendered in mock mode, the Cash page works fully in mock, and Settings has the `exception` notice.
- Focus management: amount focus on open, note focus in reversal mode, result `h2` focus on success, and focus returns to the opener or the card title.
- `aria-label` per-row reverse button (`cashReverseThisAria`), `aria-pressed` on toggles, `prefers-reduced-motion` handled in all new CSS.

**Findings**
- WARNING: at ≤375px the Cash ledger loses its primary datum. Date `nowrap` plus a 160px type column leave Amount and Status off-screen with no fade, shadow or hint that the card scrolls (`fix30/cash-320-zh.png`, `cash-375-zh.png`). Users cannot see how much a row is without discovering the horizontal scroll. See Top Fix 2.
- WARNING: the numeric collisions in the Trades table at ≤375px (see Spacing) also hurt task completion on that screen.
- WARNING: no focus trap in the modal. `aria-modal="true"` is set, but Tab leaves the dialog into the page behind it. The spec records this as accepted debt U-23 and it applies equally to OrderTicket, so it is listed rather than counted as a new defect. It is still the largest remaining keyboard gap.
- WARNING (a11y, minor): the loading text on Cash and Overview (`載入中…`) and the refreshing note (`.refresh-note`) are not in a live region, so assistive tech is not told. Only the stale state has `role="status"`.
- WARNING (pre-existing, adjacent): Trades sortable headers are `<th @click>` with no button semantics or keyboard access. The Overview watchlist `→` link is an icon-only button with no accessible name.
- INFO: submit is disabled on an empty form with the amount hint ("must be greater than 0") as the only visible reason. This is within the spec's letter (field errors appear after blur or input) but is the weakest case of rule 6. The pale submit button in `m07a-deposit-form.png` was caught mid-transition by the harness (the same flow reports `submit disabled=false`), so it is not scored.
