## 凍結契約（04.1-10 寫契約檔、前端 04.1-12 / 04.1-15 / 04.1-17 依此）

**GET `/api/v1/portfolio/cash-entries`**
- 權限 `PORTFOLIO_VIEW`；回 `ApiResponse<PageResponse<CashEntryDto>>`（`items` / `page` / `size` / `totalElements` / `totalPages`）。
- 查詢參數 `page`（預設 0，夾限 0..10000）、`size`（預設 20，夾限 1..100）；非數字 → 400 `VALIDATION_FAILED`（訊息 `page must be a number` / `size must be a number`，不帶 `fields`）。
- 排序固定 `occurredAt DESC, id DESC`，無排序／篩選參數。只含登入者自己的分錄。
- `CashEntryDto` 欄位同 04.1-04：`id`（UUID 字串）、`type`、`currency`、`amount`、`note`、`occurredAt`、`createdAt`、`reversalOfId`（沖銷分錄為原分錄 UUID，否則 null）、`reversalOfOccurredAt`（同上）、`reversed`（此分錄是否已被沖銷）。UI-SPEC 的「沖銷這筆」顯示條件 `reversalOfId == null && !reversed`。

**POST `/api/v1/portfolio/cash-entries` 的 `reversalOfId`**
- body 尾端追加 `reversalOfId`（String，選填，`@Size(max = 36)`）。帶值 = 沖銷：`type` 必須與原分錄相反、`currency` 相同、`amount` 數值相等（compareTo，scale 無關）；`note` / `occurredAt` 仍可自填，`occurredAt` 省略 = 伺服器現在。
- 仍須 `Idempotency-Key` header 與 `TRADE_EXECUTE` 權限。成功回 200 `CashEntryDto`（`reversalOfId` = 原 UUID、`reversalOfOccurredAt` = 原發生時間、`reversed` = false）；成功後列表中原分錄 `reversed = true`。
- 冪等比對維度新增「沖銷對象」：同 key 換對象、或在沖銷與一般分錄間切換 → 409 `CASH_IDEMPOTENCY_KEY_REUSED`。同 key 同 payload 重送成功過的沖銷 → 200 同一 id（冪等優先於「已沖銷」）。

**錯誤碼（字面凍結，前端 i18n 依 code 分派，不可改名）**

| code | HTTP | message（靜態） | 觸發 |
| --- | --- | --- | --- |
| `CASH_ENTRY_NOT_FOUND` | 404 | `Cash entry not found` | 原分錄不存在，或屬於他人（兩者無法區分，body 不含 UUID） |
| `CASH_ENTRY_ALREADY_REVERSED` | 409 | `Cash entry has already been reversed` | 原分錄已被沖銷；含併發落敗（另一把 key 搶先） |
| `CASH_ENTRY_NOT_REVERSIBLE` | 409 | `A reversal entry cannot be reversed` | 原分錄本身是沖銷分錄 |

**400 `VALIDATION_FAILED` 的 `error.fields.reversalOfId` 字面**
- `invalid format`：非 UUID 格式（含空白字串）。
- `must mirror the original entry`：方向未相反、幣別不同或金額不同。
- （超過 36 字元由 bean validation 產生 `fields.reversalOfId`，文字由 `GlobalExceptionHandler` 決定。）

**判斷順序（影響前端看到哪個錯誤）**：key / type / currency / occurredAt 驗證 → `reversalOfId` 格式 → 原分錄查詢（404）→ 冪等快路徑 → 沖銷規則（`NOT_REVERSIBLE` → `ALREADY_REVERSED` → 鏡像檢查）→ insert。

**稽核**：沖銷為 `cash_entry_reverse`，一般入出金仍為 `cash_entry_create`；成功 target `cash_entry:<id>`，失敗 target `cash_entry`、result `failure:<ErrorCode.name()>`。
