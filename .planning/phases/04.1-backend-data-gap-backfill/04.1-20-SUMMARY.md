## 三條旅程與判別力說明

**C1 基準幣切到 USD → 後端持久化 → Settings 與重新登入後一致**（PORT-09、D-02、D-03）
步驟：API 登入 → `/` → TWD 為 `aria-pressed=true` → 點 USD → `base-currency-switching` 消失、USD pressed、第一張 `overview-kpi` 含 `USD` → `GET /api/v1/me` 的 `baseCurrency` 為 `USD` → `nav-settings`、`settings-base-currency` 值為 `USD` → 全新 browser context 以同帳號登入，USD pressed、TWD 不 pressed。
若功能壞掉會紅：偏好只改前端狀態而沒寫回後端（PATCH 失敗 / CSRF 設錯）→ `/me` 斷言與新 context 斷言紅；偏好存 localStorage 而非後端 → 新 context 斷言紅；Settings 沒讀後端值 → Settings 斷言紅。

**C2 入金 1000 USD → 可用現金與現金頁顯示 → 一鍵沖銷後歸零**（CASH-01、CASH-03、D-11、D-24、D-25、D-29）
步驟：`overview-cash-deposit` → 對話框為入金 → 選 USD、填 1000、送出 → `cash-result-entry-id` 為完整 UUID（記下 id）→ done → `overview-kpi-cash-balances` 符合 `USD\s+1,000\.00` → 進現金頁，1 列且為 `+1,000.00 USD` → `cash-entries-reverse-{id}` → 沖銷對話框顯示原紀錄 → 送出、done → 2 列、已沖銷標記恰 1、「沖銷自」提示恰 1、整頁 `[data-testid^="cash-entries-reverse-"]` 為 0 → API：`cash-entries` `totalElements`=2、summary 的 USD 金額為 0 或不存在。
若功能壞掉會紅：入金沒寫入或重讀不到 → 可用現金卡 / 1 列斷言紅；沖銷沒建立反向列 → 2 列與 API `totalElements` 斷言紅；沖銷後原列仍可再沖或沖銷列也有按鈕（可重複沖銷）→ 反向斷言（沖銷按鈕數為 0）紅；沖銷金額方向錯 → USD 歸零斷言紅。

**C3 未入金買進 1 股 AAPL → 交易不被阻擋、各處標示 USD、現金為負**（CASH-02、TRAD-10、PORT-10、D-01、D-08、D-22、D-28）
步驟：Trades 開 ticket、選 AAPL、數量 1、送出 → `ticket-result-price` 含 `USD` 且不含 `$` → 關閉後第一個 `trades-ccy-tag` 為 `USD` → Positions 的 AAPL 列內 `positions-ccy-tag` 為 `USD` → Overview 的 `overview-kpi-cash-negative` 可見且含 `USD`、第一個 `overview-trade-ccy-tag` 為 `USD` → API：`trades` `totalElements`=1、summary 的 USD 現金 < 0、`totalEquity` ≈ `totalMarketValue + cash`（`toBeCloseTo(…, 6)`）。
若功能壞掉會紅：後端因現金不足擋下交易（違反 D-01）→ ticket 走到錯誤而非成交畫面、`totalElements`=1 斷言紅；交易幣別沒帶出 → 四處 ccy 標籤斷言紅；現金沒隨買進扣成負 → 負現金提示與 `usd.amount < 0` 紅；總資產恆等式被改壞 → `toBeCloseTo` 紅。
