## 缺陷 1:相鄰數字格間距(Trades / Overview 近期交易 / Positions)

**成因:** 三張表的 `thead th` / `tbody td` 都是 `padding: Npx 0`(水平 0)。欄寬被壓到內容最小寬時,靠右對齊的左格文字右緣與右格文字左緣之間沒有任何空隙。Positions 是同一個 pattern(brief 要求「若共用就一併修」,量測確認為真,一併修)。

**修正:** 三個 `.vue` 各加一條 `thead th + th, tbody td + td { padding-left: 12px; }`。第一欄的 inline `padding-left: 16px` 不受影響(第一欄沒有前一個兄弟);L5(表格在卡內捲動、不帶動頁面)維持綠燈。

**量測(L9):** 每格取「畫出來的東西」:文字節點的 Range rect;文字若在有底色的膠囊(type pill、幣別標籤)裡就改取膠囊 rect(膠囊貼著隔壁欄一樣是視覺黏住);排除 `.sr-only`。同一列相鄰兩格:右格內容最左緣 - 左格內容最右緣 >= 6px。只比同列相對位置,與卡內捲動位置無關。

| 項目(320px,每頁第一個資料列) | 修正前 | 修正後 |
|------|--------|--------|
| Trades:日期 / BUY 膠囊 | 0.0px | >= 12px |
| Trades:代號 / 數量、數量 / 單價 | 0.0px | >= 12px |
| Trades:總額 / 手續費 | 0.0px | >= 12px |
| Trades:手續費 / 備註 | 0.0px | >= 12px |
| 違規組數(Trades / Overview / Positions) | 42 / 13 / 32 | 0 / 0 / 0 |

375px 的違規組數與 320px 相同(欄寬在兩個寬度下都被壓到最小)。

### L9 判別力(RED 輸出)

## 缺陷 2:現金頁 < 640px

**成因:** 04.1-30 為了讓類型膠囊不逐字換行,把 `.col-type` / `.col-note` 各保底 160px;表格因此寬 685px,卡片可視寬只有 270px(320px 視窗),金額欄被推到卡內捲動後面,狀態 / 沖銷鈕更遠,而且沒有任何捲動提示。

**修正(Cash.vue):** `@media (max-width: 639px)` 內每筆紀錄 `tr` 改 `display: grid`,兩欄(`minmax(0,1fr) auto`)三列:

```
日期 (YYYY-MM-DD / HH:mm)         +123,456,789.00 TWD
[入金] [新] 沖銷註記(日期)           [沖銷這筆] / 已沖銷
備註(整列寬)
```

- `>= 640px` 的表格版面、`.col-type` / `.col-note` 的 160px 保底、備註 2 行 clamp 都沒動。
- 膠囊與金額仍是 `white-space: nowrap`(L8 的單行斷言維持綠燈);金額在 `auto` 欄,不會被擠。
- `thead` 以 sr-only 手法保留給輔助科技;table / rowgroup / row / columnheader / cell 都補明確 `role`,因為 display 改 block / grid 後瀏覽器可能丟掉表格語意。
- 日期與時間各自 nowrap(兩個 span,中間一個空格),窄螢幕只在兩者之間斷行,不會斷在日期連字號(`2026-10-` / `28`);`textContent` 仍是 `YYYY-MM-DD HH:mm`。
- testid(`cash-entries`、`cash-entries-row`、`cash-entries-reverse-*`、`cash-entries-reversed-pill` 等)全數不變;沖銷鈕仍是 `button`,`aria-label` 不變。
- 備註列(500 字)在窄螢幕仍不 clamp(沿用 04.1-30 之前的行為,clamp 只在 >= 640px),不在本 plan 範圍。

**量測(L10,zh / en x 320 / 375):** 每列的日期、類型膠囊、金額、備註、沖銷狀態、沖銷鈕,左右緣都在 `[0, innerWidth]` 內,也在卡片可視框內(卡片 border 內緣到 clientWidth);`card.scrollWidth <= card.clientWidth`(不需卡內捲動);膠囊與金額單行;整頁與 main 不水平捲動;`expectTableScrollsInsideCard` 仍成立。

| 項目 | 修正前 | 修正後 |
|------|--------|--------|
| 320px 卡片內容寬 / 可視寬 | 685px / 270px | <= 270px(不捲動) |
| 金額欄 | 在捲動後面,視窗外 | 與日期同一行,靠右,完整可見 |
| 狀態 / 沖銷鈕 | 不可達(要橫向捲動) | 第二行靠右,完整可見 |

### L10 判別力(RED 輸出)
`卡片需要水平捲動(內容寬 685px > 可視寬 270px)`,四條(320 / 375 x zh / en)全數失敗。

## Deviations from Plan

1. **[Rule 1 - 測試自身缺陷] L9 量測排除 .sr-only 文字:** 第一版把持倉「—」格內的螢幕閱讀器文字(`.sr-only`,clip + 1px)當成畫出來的內容,算出 -33px 的假違規(Positions 列 2)。這不是 RED 的失敗原因(RED 的 0.0px 違規都是真的),但修在 GREEN A 的 commit 裡,於 commit message 說明。
2. **[契約遵守] Cash.test.ts 的「spacing on the UI-SPEC scale」來源契約:** 第一版 CSS 用了 `gap: 6px`、`margin: -1px`,被該測試擋下;改為 `gap: 8px 12px`、`margin: 0`(測試未動,是設計尺度的硬契約)。
3. **[範圍補充] Positions 一併修:** brief 說「若共用 pattern 一併檢查」;量測確認同樣是 `padding: Npx 0`,L9 也含 Positions(2 條)。
4. **[範圍補充] 日期 / 時間分段 nowrap:** 第一版堆疊後 320px zh 的日期被斷成 `2026-10-` / `28 01:00`(斷在連字號),屬同一個缺陷的外觀品質,故以兩個 nowrap span 處理。`textContent` 不變,Cash.test.ts 不需調整。
5. Cash.test.ts **未修改**:DOM 契約只新增 role 屬性、拆 span,textContent 與 testid 不變。
