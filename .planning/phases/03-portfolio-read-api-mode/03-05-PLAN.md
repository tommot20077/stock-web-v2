**API mode UI ↔ 參數對應（鎖定，與 Plan 01/02 契約一致）：**

| UI 控制 | 參數 | 備註 |
|---------|------|------|
| chip `All` | 無 type/date 參數 | 預設選中 |
| chip `Buy` / `Sell` | `type=BUY` / `type=SELL` | |
| chip `Dividend` | **不渲染**——後端 TradeType 只有 BUY/SELL，永遠回不出 DIV，露出入口會讓使用者以為功能壞掉（D-02）；mock mode 保留 | |
| chip `{當年度}` | `dateFrom` / `dateTo` = 本地時區的年初/次年年初，ISO-8601 含 offset，半開區間 | 動態 `new Date().getFullYear()`，不寫死 2026（D-05）；mock mode 保留現有寫死 '2026' chip 不動 |
| 表頭 date / total / qty 點擊 | `sort=executedAt` / `total` / `quantity` + `direction` 切換 | 只有這三欄可排序（後端白名單刻意收斂）；其餘表頭不可點。初始 `sort=executedAt&direction=desc` 明確送出（D-07） |
| 上一頁/下一頁按鈕 | `page` | 顯示 `{page+1} / {totalPages}`；第 0 頁 prev 禁用、最後一頁 next 禁用（D-08） |

**D-15 規則（鎖定）：** 任何 chip 或排序變更 → `page` 重置 0 再請求。任何回應若 `items` 為空且 `page >= totalPages` 且 `totalPages > 0` → 以 `page = totalPages - 1` 自動重新請求一次（篩選後總頁數變少的回退，防止「畫面顯示空列表但其實有資料」）。

**D-10 規則（鎖定）：** 匯出以**當前 type/date/sort/direction 參數**、`size=100`（減少請求數，後端 clamp 上限）從 page 0 循環拉到 `totalPages - 1`，全部 items 組 CSV；檔名保留現有 `trades-{activeFilter}-{date}.csv` 慣例；「所有頁」不等於「忽略篩選匯出全部」——篩了 Buy 匯出的檔案不得出現 SELL。循環中任一頁失敗 → 中止、不產生部分檔案、顯示錯誤（含 code + traceId）。
</objective>
