<objective>
擴充 `GET /api/v1/trades`：新增篩選（交易類型、日期區間，D-05）與排序（`executedAt` / `total` = `quantity × price` / `quantity`，D-06）參數，預設排序改為 `executedAt` 降序加 `id` 降序 tie-breaker（D-07），並以 V9 migration 補上排序配套索引。

Purpose: server-side 分頁下，client-side 篩選/排序只作用於當前頁，是正確性缺陷而非體驗問題（PORT-08、ROADMAP Phase 3 成功判準 6）。後端不做，前端 Plan 05 的 Trades 頁就無法正確。

Output: 後端 API 契約擴充完成、V9 索引就位、unit + IT 全綠。本 plan 不動前端 repo。

**本 plan 鎖定的 API 契約（前端 Plan 02/05 依同一契約實作，不得偏移）：**

| 參數 | 型態 | 預設 | 語意 |
|------|------|------|------|
| `symbol` | string | 無（不篩） | 既有行為不變 |
| `type` | string | 無（不篩） | `BUY` / `SELL`，大小寫不敏感（走既有 `TradeType.fromApiValue`）；非法值 → 400 `TRADE_UNSUPPORTED_TYPE` |
| `dateFrom` | ISO-8601 OffsetDateTime | 無 | `executed_at >= dateFrom` |
| `dateTo` | ISO-8601 OffsetDateTime | 無 | `executed_at < dateTo`（**半開區間 `[dateFrom, dateTo)`**）；無法解析 → 400 `VALIDATION_FAILED` |
| `sort` | string | `executedAt` | 白名單：`executedAt` / `total` / `quantity`；非法值 → 400 `VALIDATION_FAILED` |
| `direction` | string | `desc` | `asc` / `desc`，大小寫不敏感；非法值 → 400 `VALIDATION_FAILED` |
| `page` / `size` | int | 0 / 20 | 既有 clamp 沿用（page ≤ 10000、size 1..100） |

所有排序一律附加 `, t.id {direction}` 作為決定性 tie-breaker。日期篩選與排序皆以 `executed_at`（成交時間）為準，非 `created_at`（入帳時間）。
</objective>
