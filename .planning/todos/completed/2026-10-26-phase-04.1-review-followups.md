四項 warning 皆不阻擋 Phase 04.1 收尾(無 critical / high),處置為「記待辦」:

## WR-02 一筆不合法的 assets 資料會讓 summary / holdings / trades 全部 500(最值得先做)
`AssetFacadeImpl` 對 `currency`、`asset_type` 以未防護的 `valueOf` 轉 enum;`assets.currency` 在 V1 為 `VARCHAR(10) NOT NULL` 且**沒有 CHECK 約束**
(`users.base_currency` 與 `cash_ledger_entries.currency` 都有)。`FxRateFacadeImpl` 已會略過壞列,`AssetFacadeImpl` 沒有。
目前 `assets` 只能經 migration / 直接改庫寫入(資產管理介面為 Deferred D-20),`asset_type` 的 `valueOf` 本就是既有寫法,故風險是潛在的。
方向:壞列略過並 WARN(只記 id),或補 `ck_assets_currency` CHECK(與 `CurrencyCode` 一致);兩者可並用。資產管理介面做之前務必處理。
(審查報告引的行號 335-343 與實際檔案不符,以 `mapProfile` / `valueOf` 呼叫處為準。)

## WR-01 基準幣總額使用靜態 seed 匯率,畫面沒有標示匯率時間
D-04 已決定匯率為靜態 seed、即時匯率為 Deferred;但使用者看不到匯率是哪一天的。方向:summary 回傳 `fxRateTime`(或最舊匯率時間),
Overview 在總額旁小字標示「匯率更新於 …」;接真匯率來源時一併做。

## WR-03 readOnly 交易註解寫「共用快照」但隔離層級是 READ COMMITTED
**更新 2026-10-31:** 現金分錄列表 `CashLedgerService#listEntries` 已改 `REPEATABLE_READ`(PR #50 Codex review P2,04.1-33,附反射測試);**仍待處理:** `TradingService#listTrades`(Phase 4 既有,同樣 count + list 兩道述句)與 `PortfolioQueryService`。
summary 與列表總額在極端情況下可能不一致,且 summary 快取 60 秒。方向:要快照一致就改 `REPEATABLE READ` readOnly,或把註解改成實際保證。
風險低(單使用者資料、append-only 帳本),優先序最低。

## WR-04 現金金額以 JSON double 送出,極大值被無聲四捨五入
後端驗證到小數 8 位、上限 1e12(約 20 位有效數字),前端 `CashEntryDialog` / `cashApi.ts` 以 JS number 序列化。一般金額(< 約 1e7 且 ≤ 2 位小數)無影響;
極端值會被悄悄改寫。方向:送字串金額(後端以 BigDecimal 解析)或限制前端可輸入位數;改契約屬跨 repo 變更,需同步契約檔與 E2E。
